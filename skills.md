# Packaging Barev-Purple for Maemo-Leste

## Overview

### Components

1. **Backend Plugin (`libbarev.so`)**
   - A libpurple plugin (PRPL) forked from `prpl-bonjour`, implementing XMPP over Yggdrasil IPv6.
   - Internally still uses `"bonjour"` as the debug category string (historical, not yet renamed).
   - Installed to `/usr/lib/arm-linux-gnueabihf/purple-2/`.
   - Handled by **Telepathy-Haze** as `haze/barev`.

2. **UI Plugin (`rtcom-accounts-plugin-barev`)**
   - A separate repo/package: `rtcom-accounts-plugin-barev` (`maemo/excalibur` branch).
   - Provides the "Conversations" account creation UI via `librtcom-accounts-widgets`.
   - Autotools-based, modeled on `rtcom-accounts-plugin-facebook`.
   - Depends on `barev-purple`.

3. **Telepathy Manager File (`haze.manager`)**
   - `/usr/share/telepathy/managers/haze.manager` — declares the haze CM and barev protocol to Mission Control.
   - Only installed on Maemo (via `debian/install` in `maemo/excalibur`); not relevant for desktop Pidgin.

## Branch Strategy

| Branch | Purpose | Icons | `debian/` |
|---|---|---|---|
| `main` | Desktop / Pidgin | black | absent |
| `maemo/excalibur` | Maemo Leste `.deb` | white | present |

All `.c`/`.h` sources are identical between branches. The only Makefile difference is which icon variant (`_black` or `_white`) gets installed as `barev.png`.

All icon source files live in `logo/` with explicit suffixes:
- `logo/16/barev_black.png`, `logo/16/barev_white.png`
- `logo/22/barev_black.png`, `logo/22/barev_white.png`
- `logo/48/barev_black.png`, `logo/48/barev_white.png`
- `logo/scalable/barev.svg` (black, desktop), `logo/scalable/barev_white.svg`

`barev.svg` was generated by `potrace` from the original PNG of the Armenian letter բ. It has `fill="#000000"` and is used in Pidgin's scalable icon slot. Maemo uses fixed-size PNGs.

White icons are needed because Maemo's Hildon theme is dark. The HAM app manager uses the 48×48 PNG for the package icon.

## Security Model

Whitelist-only: unknown peers are rejected immediately. Both nick AND IP must match a known contact.

- `conv_match_by_ip`: rejects a connection from a known IP if the stream `from` JID has a different localpart.
- `validate_ip_consistency`: rejects a connection from the right nick if the peer IP doesn't match the stored IP for that buddy.
- When the stream `from` JID encodes an IPv6 address, `getpeername()` is called to verify the actual peer IP matches — prevents impersonation since Yggdrasil IPs are cryptographically bound to public keys.
- Unknown peers receive a `not-authorized` stream error and are disconnected immediately.
- Contacts must be added explicitly via osso-abook; the chain is osso-abook → EDS → Mission Control → haze → `barev_add_buddy`.
- Persistent contacts file: `~/.purple/barev-contacts-<nick>.conf`, loaded on login, written on add/remove/close.

## Plugin Internals — Crash Fixes

### MSG_NOSIGNAL on all send() calls
All seven `send()` calls in `jabber.c` use `MSG_NOSIGNAL`. Without it, a broken Yggdrasil socket delivers `SIGPIPE` inside `bonjour_jabber_close_conversation` or the TX write callback, potentially crashing Pidgin if the signal handler is not set to `SIG_IGN` at that instant. With `MSG_NOSIGNAL`, a broken-pipe is returned as `EPIPE` via errno instead.

### Ping timer stale-pointer check
`bonjour_jabber_ping_timer_cb` captures `pb` and `bb` before calling `bonjour_jabber_send_ping_request(bconv)`. That call can internally invoke `bonjour_jabber_close_conversation(bconv)` → `g_free(bconv)`. After the call, the timer checks `bb->conversation != bconv`: `close_conversation` sets `bb->conversation = NULL` before freeing, so a mismatch means bconv is dead and the timer returns `FALSE` (do not reschedule).

## Telepathy Presence Integration

### How the Maemo status applet gets presence types

The chain is: libpurple PRPL `bonjour_status_types()` → telepathy-haze → Mission Control → status applet.

The status applet queries MC for available presences per protocol. MC queries the haze Protocol D-Bus object at `/org/freedesktop/Telepathy/ConnectionManager/haze/barev` for the `Protocol.Interface.Presences.Statuses` property. **Haze returns an empty array for barev** — it implements the interface via `TpBaseProtocol` but does not populate statuses for this protocol.

### Fix: static declarations in haze.manager

MC falls back to statically declared presences in the manager file. The format is `status-<id>=type:<u> may-set-on-self:<b> can-have-message:<b>`:

```ini
[ConnectionManager]
BusName=org.freedesktop.Telepathy.ConnectionManager.haze
ObjectPath=/org/freedesktop/Telepathy/ConnectionManager/haze

[Protocol barev]
param-account=s required
...
Interfaces=org.freedesktop.Telepathy.Protocol.Interface.Presence;
status-available=type:2 may-set-on-self:true can-have-message:true
status-away=type:3 may-set-on-self:true can-have-message:true
status-busy=type:6 may-set-on-self:true can-have-message:false
status-offline=type:1 may-set-on-self:false can-have-message:false
```

Telepathy presence type numbers: offline=1, available=2, away=3, extended_away=4, hidden=5, busy=6.

### Maemo status applet behavior

The Hildon status applet has exactly **three slots**: Online, Busy, Offline. Away (type 3) is never shown regardless of what the CM declares — this is a deliberate Maemo UX decision inherited from Fremantle (on a phone you always carry, "away" is considered meaningless). The same applies to XMPP/gabble.

### Verifying haze Protocol presences via dbus

```bash
dbus-send --session --print-reply \
  --dest=org.freedesktop.Telepathy.ConnectionManager.haze \
  /org/freedesktop/Telepathy/ConnectionManager/haze/barev \
  org.freedesktop.DBus.Properties.GetAll \
  string:"org.freedesktop.Telepathy.Protocol.Interface.Presences"
```

### Verifying Connection SimplePresence statuses (live connection)

```bash
dbus-send --session --print-reply \
  --dest=org.freedesktop.Telepathy.ConnectionManager.haze \
  /org/freedesktop/Telepathy/ConnectionManager/haze/barev/ACCOUNT_SUFFIX \
  org.freedesktop.DBus.Properties.Get \
  string:"org.freedesktop.Telepathy.Connection.Interface.SimplePresence" \
  string:"Statuses"
```

### Setting presence via dbus

```bash
dbus-send --session --print-reply \
  --dest=org.freedesktop.Telepathy.ConnectionManager.haze \
  /org/freedesktop/Telepathy/ConnectionManager/haze/barev/ACCOUNT_SUFFIX \
  org.freedesktop.Telepathy.Connection.Interface.SimplePresence.SetPresence \
  string:"away" string:""
```

## Debian Packaging

### `debian/install` — format rules

- The second field is a **destination directory relative to the package root**, not an absolute path.
- Use glob patterns for multiarch paths.
- To install a file from the source tree (not from `make install` staging), use `source_file dest_dir/`:

```
/usr/lib/*/purple-2/libbarev.so
/usr/share/pixmaps/pidgin/protocols/16/barev.png
/usr/share/pixmaps/pidgin/protocols/22/barev.png
/usr/share/pixmaps/pidgin/protocols/48/barev.png
/usr/share/pixmaps/pidgin/protocols/scalable/barev.svg
haze.manager usr/share/telepathy/managers/
```

**Wrong**: `haze.manager /usr/share/telepathy/managers/haze.manager` — dh_install treats the second field as a directory, creating `haze.manager/haze.manager`.  
**Right**: `haze.manager usr/share/telepathy/managers/`

### `debian/rules`

```makefile
#!/usr/bin/make -f

override_dh_auto_install:
	$(MAKE) install DESTDIR=$(CURDIR)/debian/barev-purple

%:
	dh $@
```

### `debian/source/format`

Must NOT exist, or must say `3.0 (native)`. With `3.0 (quilt)`, gbp rejects versions without a `-X` Debian revision.

### Multiarch plugin path

On armhf, `pkg-config --variable=plugindir purple` returns `/usr/lib/arm-linux-gnueabihf/purple-2`, not `/usr/lib/purple-2`. Always use `*` glob in `debian/install`.

## Forgejo CI/CD

- Forgejo at `git.maemo.org` builds packages on push to `maemo/excalibur`.
- The CI appends a build number suffix: `2.8` becomes `2.8+5m7`.
- `gbp` reads the `debian/changelog` version, strips any Debian revision after `-`, and looks for that tag.
- **The tag must match the changelog version exactly.**
- `secrets: inherit` is required in the workflow — without it the CI runner cannot publish packages (401 error).

### Tag workflow

```bash
git tag 2.8
git push maemo :refs/tags/2.8   # delete old remote tag if retagging
git push maemo refs/tags/2.8
git push maemo HEAD:maemo/excalibur
```

### Changelog and tag must be in sync

The `debian/changelog` entry for version N must be committed **before** tagging N. The tag should point to the commit that includes the changelog bump, not to a prior functional commit.

### Required `.forgejo/workflows/build.yml`

```yaml
on:
  workflow_call:
  push:
  pull_request:
    types: [opened, synchronize, reopened]

enable-email-notifications: true

jobs:
  call-reusable-workflow:
    uses: leste-cicd/forgejo-workflows/.forgejo/workflows/maemo-entry.yml@master
    secrets: inherit
```

## yggdrasil postinst setup

The `barev-purple` postinst creates `/etc/init.d/yggdrasil` and `/etc/yggdrasil/yggdrasil.conf` if absent. The generated config is patched with public peers and `IfName: barev0`.

Key sed commands (yggdrasil config uses 2-space indentation):

```sh
sed -i 's/^  Peers: \[\]/  # Peers: []/' "$CONF"
sed -i "/^  # Peers: \[\]/r $PEERS_FILE" "$CONF"
sed -i 's/^  IfName: .*/  IfName: barev0/' "$CONF"
```

Use a temp file (`mktemp` + heredoc) to insert the peers line — avoids shell quoting issues with double-quoted peer URIs.

## Autotools packages (rtcom-accounts-plugin-barev)

Automake fails if these files are missing from the repo root: `AUTHORS`, `ChangeLog`, `NEWS`, `README`.

Dynamic service detection — always use `tp_list_connection_managers_async`, never hardcode `haze/barev`:

```c
for (l = cms; l; l = l->next) {
    if (tp_connection_manager_has_protocol(l->data, "barev")) {
        gchar *service_id = g_strconcat(
            tp_connection_manager_get_name(l->data), "/barev", NULL);
        rtcom_account_plugin_add_service(plugin, service_id);
        g_free(service_id);
    }
}
```
